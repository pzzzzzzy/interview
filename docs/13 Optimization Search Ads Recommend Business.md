## 二、优化算法基础

### 2.1 优化问题的数学框架

#### 标准形式

**无约束优化**:

```
最小化: f(x)
其中: x ∈ R^n

例子:
最小化损失函数 L(θ) = Σ(y - ŷ)²
```

**有约束优化**:

```
最小化: f(x)
约束条件:
  g_i(x) ≤ 0  (不等式约束)
  h_j(x) = 0  (等式约束)

例子:
最小化: 成本
约束: 预算 ≤ 100万
      产量 ≥ 1000件
```

---

### 2.2 梯度下降及其变体

#### 标准梯度下降 (Gradient Descent)

**原理**: 沿着负梯度方向迭代

```
算法:
x_{t+1} = x_t - η ∇f(x_t)

其中:
- x_t: 当前参数
- η: 学习率
- ∇f(x_t): 梯度

直观理解:
梯度 = 函数增长最快的方向
负梯度 = 函数下降最快的方向
→ 沿着负梯度走，函数值会下降
```

**三种变体**:

```
1. Batch Gradient Descent (批量梯度下降)
   - 每次用全部数据计算梯度
   - 优点: 收敛稳定
   - 缺点: 慢，内存占用大

2. Stochastic Gradient Descent (随机梯度下降)
   - 每次用一个样本计算梯度
   - 优点: 快，可以跳出局部最优
   - 缺点: 震荡大，不稳定

3. Mini-batch Gradient Descent (小批量梯度下降)
   - 每次用一小批样本（如32、64、128）
   - 优点: 平衡速度和稳定性
   - 缺点: 需要调batch size
   - 实际最常用 ✓
```

---

#### 动量法 (Momentum)

**问题**: 标准梯度下降在峡谷地形容易震荡

```
可视化:
     |  /\  /\  /\
     | /  \/  \/  \
     |/            \
     ───────────────→

震荡严重，收敛慢
```

**动量法**: 引入"惯性"

```
算法:
v_t = β v_{t-1} + ∇f(x_t)
x_{t+1} = x_t - η v_t

其中:
- v_t: 速度（累积的梯度）
- β: 动量系数（通常0.9）

效果:
- 在一致的方向上加速
- 在震荡的方向上减速
- 收敛更快更稳定
```

**类比**: 滚球下山

```
没有动量:
- 球每步都重新计算方向
- 遇到小坑会停下

有动量:
- 球有惯性，会越滚越快
- 小坑不会阻挡，可以冲过去
```

---

#### Adam优化器

**全称**: Adaptive Moment Estimation

**核心思想**: 自适应学习率 + 动量

```
算法:
m_t = β_1 m_{t-1} + (1-β_1) ∇f(x_t)     # 一阶动量（均值）
v_t = β_2 v_{t-1} + (1-β_2) (∇f(x_t))²  # 二阶动量（方差）

# 偏差修正
m̂_t = m_t / (1 - β_1^t)
v̂_t = v_t / (1 - β_2^t)

# 参数更新
x_{t+1} = x_t - η m̂_t / (√v̂_t + ε)

默认参数:
- β_1 = 0.9
- β_2 = 0.999
- ε = 10^-8
```

**优势**:

```
1. 自适应学习率
   - 梯度大的参数 → 学习率小（防止震荡）
   - 梯度小的参数 → 学习率大（加速收敛）

2. 结合动量
   - 收敛快且稳定

3. 鲁棒性好
   - 对学习率不敏感
   - 大多数情况下效果好

实践:
- 深度学习的默认选择
- 通常不需要调参就能工作良好
```

### 2.3 凸优化与非凸优化

#### 凸函数

**定义**: 函数的任意两点连线在函数上方

```
数学定义:
f(λx + (1-λ)y) ≤ λf(x) + (1-λ)f(y)
对所有 x, y 和 λ ∈ [0,1]

直观:
      ·───·
     /     \
    /       \
   /         \
  ·───────────·

碗状，只有一个最低点
```

**性质**:

```
✓ 局部最优 = 全局最优
✓ 梯度下降一定收敛到全局最优
✓ 理论保证强

例子:
- 线性回归的MSE损失
- Logistic回归的交叉熵损失
- L2正则化
```

---

#### 非凸函数

**特点**: 有多个局部最优

```
直观:
    ·    ·
   / \  / \
  /   ··   \
 /          \
·────────────·

多个"坑"，容易陷入局部最优
```

**挑战**:

```
❌ 梯度下降可能陷入局部最优
❌ 难以找到全局最优
❌ 初始化很重要

例子:
- 神经网络的损失函数（非凸）
- K-means的目标函数
```

**应对策略**:

```
1. 多次随机初始化
   - 从不同起点开始优化
   - 选择最好的结果

2. 使用动量、Adam等高级优化器
   - 帮助跳出局部最优

3. 学习率调度
   - 初期大学习率（探索）
   - 后期小学习率（精细调整）

4. 正则化
   - L1/L2正则化
   - Dropout
   - 让损失函数更"平滑"
```

### 2.4 约束优化与拉格朗日乘数法

#### 拉格朗日乘数法

**问题**: 带等式约束的优化

```
最小化: f(x, y)
约束: g(x, y) = 0

例子:
最小化: x² + y²  (到原点的距离)
约束: x + y = 1  (在直线上)
```

**方法**: 构造拉格朗日函数

```
L(x, y, λ) = f(x, y) + λ g(x, y)

其中 λ 是拉格朗日乘数

求解:
∂L/∂x = 0
∂L/∂y = 0
∂L/∂λ = 0  (即约束条件)
```

**直观理解**:

```
最优点:
f的梯度 与 g的梯度 平行

即: ∇f = -λ ∇g

意义:
- 不能再沿着g的切线方向减小f
- 只能沿着g的法线方向（但这会违反约束）
```

---

#### KKT条件 (Karush-Kuhn-Tucker)

**问题**: 带不等式约束的优化

```
最小化: f(x)
约束: 
  g_i(x) ≤ 0  (i=1,...,m)
  h_j(x) = 0  (j=1,...,p)
```

**KKT条件** (最优解的必要条件):

```
1. 平稳性: ∇f + Σ μ_i ∇g_i + Σ λ_j ∇h_j = 0

2. 原始可行性:
   g_i(x) ≤ 0
   h_j(x) = 0

3. 对偶可行性:
   μ_i ≥ 0

4. 互补松弛性:
   μ_i g_i(x) = 0

解释:
- 如果约束不紧（g_i < 0），则μ_i = 0（约束不起作用）
- 如果约束紧（g_i = 0），则μ_i ≥ 0（约束起作用）
```

**应用**: SVM、投资组合优化、资源分配

### 2.5 商业场景中的优化问题

#### 案例1: 营销预算分配

**问题描述**:

```
公司有100万营销预算，要分配到4个渠道:
- 电视广告
- 社交媒体
- 搜索引擎
- 线下活动

目标: 最大化销售额

已知: 每个渠道的ROI曲线（边际收益递减）
```

**数学建模**:

```
最大化: R(x) = Σ R_i(x_i)
        
约束:
  Σ x_i ≤ B  (预算约束)
  x_i ≥ 0    (非负约束)

其中:
- x_i: 分配给渠道i的预算
- R_i(x_i): 渠道i的收益函数（通常是凹函数）
- B: 总预算

收益函数示例:
R_i(x) = a_i log(x + 1)  (边际收益递减)
```

**求解思路**:

```
方法1: 拉格朗日乘数法
- 构造拉格朗日函数
- 求一阶导数 = 0
- 得到最优分配

方法2: 贪心算法（近似）
1. 计算每个渠道的边际ROI
2. 把预算分配给边际ROI最高的渠道
3. 更新边际ROI，重复

方法3: 动态规划
- 离散化预算
- 逐步决策
```

**商业洞察**:

```
最优解的特点:
- 各渠道的边际ROI相等（拉格朗日乘数的经济学意义）
- 高效渠道分配更多预算
- 但要考虑边际收益递减

实际考虑:
- 渠道之间可能有协同效应
- 品牌长期价值 vs 短期销售
- 竞争对手的动作
```

#### 案例2: 库存优化

**问题**: 零售商的库存策略

```
场景:
- 产品有固定订购成本（每次订货固定费用）
- 有存储成本（每件每天的仓储费）
- 有缺货成本（顾客不满、销售损失）
- 需求有波动

目标: 最小化总成本

决策: 何时订货？订多少？
```

**经典模型: EOQ (Economic Order Quantity)**

```
假设:
- 需求率恒定 D（件/年）
- 订购成本 S（元/次）
- 持有成本 H（元/件/年）

最优订货量:
Q* = √(2DS/H)

订货周期:
T* = Q*/D

总成本:
TC = (D/Q)S + (Q/2)H

推导:
- (D/Q)S: 年订购成本（订购次数 × 单次成本）
- (Q/2)H: 年持有成本（平均库存 × 单位成本）
- 对Q求导 = 0，得Q*
```

**商业洞察**:

```
平衡:
- 订货量大 → 订购次数少（省订购成本）但库存高（存储成本高）
- 订货量小 → 订购次数多（订购成本高）但库存低（省存储成本）
- 最优点在两者平衡处

实际扩展:
- 需求不确定 → 安全库存
- 多产品 → 联合订货
- 供应商折扣 → 分段成本函数
```

#### 案例3: 定价优化

**问题**: 产品定价策略

```
目标: 最大化利润

已知:
- 成本 C
- 需求函数 D(p)（价格越高，需求越低）
- 竞争对手价格

决策: 定价 p
```

**数学模型**:

```
利润函数:
π(p) = (p - C) × D(p)

需求函数（线性）:
D(p) = a - b·p

其中:
- a: 基础需求
- b: 价格敏感度（价格弹性）

最大化利润:
dπ/dp = 0

解得:
p* = (a/b + C) / 2

洞察:
- 最优价格 = (市场最高可接受价格 + 成本) / 2
- 在成本和需求之间找平衡
```

**价格弹性分析**:

```
价格弹性:
ε = (ΔD/D) / (Δp/p) = (dD/dp) × (p/D)

解释:
- |ε| > 1: 弹性大（降价增加总收入）
- |ε| < 1: 弹性小（涨价增加总收入）
- |ε| = 1: 单位弹性（改价不影响总收入）

商业决策:
- 必需品（牙膏）: 弹性小，可以涨价
- 奢侈品（名牌包）: 弹性大，降价促销效果好
- 垄断产品: 弹性小
- 竞争激烈产品: 弹性大
```

**动态定价**:

```
场景: 电商促销、航空机票、酒店房间

策略:
- 需求高时（旺季、节假日）: 高价
- 需求低时（淡季、工作日）: 低价
- 临近时间（机票起飞前、酒店入住前）: 动态调整

算法:
- 强化学习（Q-learning、DQN）
- 预测模型 + 优化
- A/B测试找最优价格
```

### 3.1 推荐系统基础

#### 推荐系统的商业价值

```
电商（亚马逊、淘宝）:
- 提高转化率

```

**核心指标**:

```
业务指标:
- GMV（成交额）
- CTR（点击率）= 点击数 / 曝光数
- CVR（转化率）= 转化数 / 点击数
- 人均时长
- 留存率

算法指标:
- AUC（曲线下面积）
- NDCG（归一化折损累积增益）
- MRR（平均倒数排名）
- Precision@K、Recall@K
```

---

#### 协同过滤 (Collaborative Filtering)

**核心思想**: 利用群体智慧

```
"喜欢相似物品的用户，可能也会喜欢这些用户喜欢的其他物品"
"和你相似的用户喜欢的东西，你可能也会喜欢"
```

**用户协同过滤 (User-based CF)**:

```
步骤:
1. 找到和目标用户相似的用户（邻居）
2. 推荐邻居喜欢的物品

相似度计算（余弦相似度）:
sim(u, v) = cosine(R_u, R_v)
          = Σ R_ui × R_vi / (||R_u|| × ||R_v||)

其中 R_u 是用户u的评分向量

预测评分:
r̂_ui = r̄_u + (Σ sim(u,v) × (r_vi - r̄_v)) / (Σ |sim(u,v)|)
```

**物品协同过滤 (Item-based CF)**:

```
步骤:
1. 计算物品之间的相似度
2. 推荐和用户已喜欢物品相似的物品

优点 vs User-based:
- 物品数量通常 < 用户数量，计算量小
- 物品相似度稳定（用户兴趣变化快）
- 更容易解释（"因为你喜欢A，推荐相似的B"）

应用:
- 亚马逊："购买此商品的顾客也购买了..."
- Netflix: 电影推荐
```

**矩阵分解 (Matrix Factorization)**:

```
思想: 用户和物品都映射到潜在特征空间

用户-物品评分矩阵:
R ≈ U × V^T

其中:
- R: m×n评分矩阵（用户×物品）
- U: m×k用户特征矩阵
- V: n×k物品特征矩阵
- k: 潜在因子数量（如20-100）

预测:
r̂_ui = u_u^T v_i = Σ u_uk × v_ik

优化目标（最小化）:
L = Σ (r_ui - u_u^T v_i)² + λ(||u_u||² + ||v_i||²)
    (u,i)∈observed

方法:
- ALS (Alternating Least Squares)
- SGD (Stochastic Gradient Descent)

优势:
- 处理稀疏矩阵
- 可以引入偏置、时间因素
- 可解释性（潜在因子可能对应类别、风格等）
```

---

#### 深度学习推荐模型

**Deep Neural Networks (DNN)**:

```
架构:
输入层 → Embedding层 → 全连接层 → 输出层
```

```
融合:
y = σ(W_wide^T x + W_deep^T a + b)

优势:
- 结合记忆和泛化
- 既能捕捉规则，又能学习模式
```

**DeepFM**:

```
FM部分:
- 二阶特征交叉

DNN部分:
- 高阶特征交叉

优势:
- 端到端学习
- 无需人工特征工程
- 兼顾低阶和高阶交叉
```

### 3.2 搜索算法

#### 搜索系统架构

```
用户查询
   ↓
查询理解（Query Understanding）
   ↓
召回（Recall）- 从海量候选中快速筛选
   ↓
粗排（Pre-ranking）- 初步排序
   ↓
精排（Ranking）- 精细排序
   ↓
重排（Re-ranking）- 多样性、业务规则
   ↓
返回结果
```

**各阶段说明**:

```
召回（Recall）:
- 目标: 快速找到相关候选（几百到几千）
- 方法: 倒排索引、向量检索、协同过滤
- 要求: 速度快（毫秒级），覆盖率高

粗排（Pre-ranking）:
- 目标: 初步排序（留下几十到几百）
- 方法: 简单模型（LR、GBDT）
- 要求: 速度较快（几十毫秒）

精排（Ranking）:
- 目标: 精确排序（前10-20个）
- 方法: 复杂模型（DNN、Transformer）
- 要求: 准确性高（百毫秒级可接受）

重排（Re-ranking）:
- 目标: 多样性、去重、业务规则
- 方法: 启发式规则、强化学习
- 要求: 用户体验好
```

#### BM25算法

**作用**: 文本相关性打分（信息检索经典算法）

**公式**:

```
score(D, Q) = Σ IDF(q_i) × (f(q_i, D) × (k_1 + 1)) / 
              (f(q_i, D) + k_1 × (1 - b + b × |D| / avgdl))

其中:
- D: 文档
- Q: 查询
- q_i: 查询中的第i个词
- f(q_i, D): 词q_i在文档D中的频率
- |D|: 文档D的长度
- avgdl: 平均文档长度
- k_1, b: 超参数（通常k_1=1.5, b=0.75）

IDF(q_i) = log((N - n(q_i) + 0.5) / (n(q_i) + 0.5))
- N: 文档总数
- n(q_i): 包含q_i的文档数
```

**直观理解**:

```
三个因子:
1. TF（词频）: 词在文档中出现越多，越相关
   - 但有饱和效应（出现10次 vs 100次差异不大）

2. IDF（逆文档频率）: 稀有词权重高
   - "的"、"是"权重低（常见词）
   - "机器学习"权重高（专业词）

3. 文档长度归一化: 避免长文档占优
   - 长文档自然包含更多词，需要惩罚
```

#### 向量检索 (Vector Search)

**核心思想**: 将查询和文档映射到向量空间，计算相似度

```
流程:
1. 文档编码: doc → vector_d (如768维)
2. 查询编码: query → vector_q
3. 相似度计算: similarity(vector_q, vector_d)
4. 返回Top-K

编码器:
- BERT、Sentence-BERT
- OpenAI Embedding API
- 双塔模型（Query塔、Doc塔）
```

**相似度度量**:

```
1. 余弦相似度:
   cos(q, d) = q·d / (||q|| ||d||)
   范围: [-1, 1]，越大越相似

2. 欧氏距离:
   dist(q, d) = ||q - d||
   越小越相似

3. 内积:
   q·d = Σ q_i × d_i
   越大越相似（前提：向量归一化）
```

**近似最近邻搜索 (ANN)**:

```
问题: 精确搜索太慢（百万、千万级文档）

解决: 近似算法
- HNSW (Hierarchical Navigable Small World)
- IVF (Inverted File Index)
- LSH (Locality Sensitive Hashing)

速度 vs 准确率:
- 精确搜索: 100% 准确，但慢
- ANN: 95%+ 准确，快100-1000倍

工具:
- Faiss (Facebook)
- Annoy (Spotify)
- HNSW (hnswlib)
```

#### 广告系统架构

```
广告主 → 投放广告
   ↓
广告引擎（匹配、排序）
   ↓

   ↓

   ↓

   ↓
平台分成
```

**三方博弈**:

```
用户:
- 希望看到相关的广告（不打扰）
- 不希望广告太多

广告主:
- 希望ROI高（投入产出比）
- 希望精准投放

平台:
- 希望收入最大化
- 希望用户体验好（长期价值）

平衡: 长期价值 vs 短期收入
```

#### 点击率预估 (CTR Prediction)

**问题定义**:

```
输入: 用户特征 + 广告特征 + 上下文特征
输出: 点击概率 P(click | user, ad, context)

特征:
- 用户: ID、年龄、性别、地域、历史行为
- 广告: ID、类目、品牌、创意
- 上下文: 时间、设备、页面位置

目标: 预测点击概率，用于排序
```

**Logistic回归 (LR)**:

```
模型:
P(click) = σ(w^T x) = 1 / (1 + e^(-w^T x))

特点:
- 简单、快速
- 可解释性强
- 但需要人工特征工程（特征交叉）

特征工程:
- 单特征: age, gender
- 二阶交叉: age × gender
- 三阶交叉: age × gender × category
- 组合爆炸！
```

**GBDT + LR**:

```
流程:
1. GBDT学习特征表示
   - 自动特征组合
   - 输出叶子节点编号

2. LR学习点击率
   - 输入: GBDT的叶子节点（one-hot）
   - 输出: 点击概率

优势:
- GBDT自动特征工程
- LR快速在线预测
- Facebook 2014年方案
```

**深度学习模型**:

```
DNN:
- Embedding层（处理高维稀疏特征）
- 全连接层（学习特征交叉）
- 输出层（sigmoid）

Wide & Deep:
- Wide: LR（记忆）
- Deep: DNN（泛化）
- 结合两者优势

DeepFM:
- FM（二阶交叉）
- DNN（高阶交叉）
- 端到端学习

实际应用:
- Google: Wide & Deep
- 华为: DeepFM
- 阿里: DIN (Deep Interest Network)
```

---

#### 转化率预估 (CVR Prediction)

**问题**: 预测点击后的转化概率

```
P(conversion | click)

转化定义:
- 电商: 下单、支付
- APP: 安装、注册
- 游戏: 付费

挑战:
- 样本稀疏（点击很多，转化很少）
- 样本偏差（只有点击的样本）
```

**ESMM (Entire Space Multi-Task Model)**:

```
思想: 联合建模CTR和CVR

任务:
- CTR: P(click | impression)
- CVR: P(conversion | click)  ← 直接建模有偏差
- CTCVR: P(click, conversion | impression)

关系:
P(click, conversion) = P(click) × P(conversion | click)
CTCVR = CTR × CVR

模型:
- 共享Embedding
- 两个塔: CTR塔、CVR塔
- 联合训练

优势:
- 解决样本偏差
- 解决数据稀疏
- 阿里提出，广泛应用
```

---

#### 竞价与拍卖机制

**广告排序**:

```
不是按出价排序，而是按 eCPM 排序

eCPM (effective Cost Per Mille):
eCPM = bid × CTR × 1000

解释:
- bid: 广告主出价（如1元/点击）
- CTR: 预估点击率（如5%）
- eCPM: 期望千次曝光收入
  = 1 × 0.05 × 1000 = 50元

排序依据: eCPM从高到低
```

**GSP (Generalized Second Price)**:

```
第二价格拍卖:
- 赢家按第二名的价格付费（加1分钱）

例子:
广告A: bid=10元, CTR=10%, eCPM=1000
广告B: bid=8元, CTR=15%, eCPM=1200
广告C: bid=6元, CTR=8%, eCPM=480

排序: B > A > C
B的付费: A的eCPM / B的CTR = 1000 / 0.15 = 6.67元

优势:
- 激励真实出价（不需要猜测对手）
- 纳什均衡
- Google AdWords使用
```

**VCG (Vickrey-Clarke-Groves)**:

```
更复杂的拍卖机制:
- 考虑社会福利最大化
- 每个广告主按"对其他人造成的损失"付费

理论最优，但实际较少用（复杂度高）
```

### 3.4 推荐系统的商业考量

#### 多目标优化

**问题**: 不只优化点击率，还要考虑多个目标

```
电商推荐:
- 点击率（短期）
- 转化率（直接收益）
- 客单价（高价值商品）
- 用户满意度（长期留存）
- 多样性（避免信息茧房）

视频推荐:
- 点击率
- 完播率
- 点赞/分享率
- 观看时长
- 内容健康度

权衡:
- 只优化点击率 → 标题党、低质内容
- 只优化收入 → 过度推荐高价商品，用户反感
- 需要平衡短期和长期目标
```

**多目标建模方法**:

```
方法1: 加权求和
score = w_1 × CTR + w_2 × CVR + w_3 × price + ...

权重确定:
- 业务目标（如GMV = CTR × CVR × price）
- A/B测试调优
- 专家经验

方法2: 多任务学习
- 共享底层特征
- 多个输出头（CTR头、CVR头、时长头）
- 联合优化

方法3: 强化学习
- 长期价值 vs 短期收益
- 学习最优策略
```

---

#### 冷启动问题

**问题**: 新用户、新商品没有历史数据

```
新用户冷启动:
- 没有行为数据，无法协同过滤
- 解决:
  1. 引导式问卷（收集兴趣）
  2. 热门推荐（大众喜好）
  3. 基于人口统计学（年龄、性别）
  4. 内容特征（冷启动期用内容推荐）

新商品冷启动:
- 没有交互数据，无法计算相似度
- 解决:
  1. 基于内容特征（类目、属性、描述）
  2. 流量扶持（给新商品一定曝光）
  3. Exploration（探索）vs Exploitation（利用）
```

**Exploration vs Exploitation**:

```
Exploitation（利用）:
- 推荐已知的好物品
- 短期收益高
- 但可能错过更好的物品

Exploration（探索）:
- 尝试新物品
- 短期收益可能低
- 但发现潜力商品，长期收益高

平衡策略:
1. ε-greedy:
   - 以ε概率随机推荐（探索）
   - 以1-ε概率推荐最优（利用）

2. UCB (Upper Confidence Bound):
   - 考虑不确定性
   - 给不确定的物品更高权重

3. Thompson Sampling:
   - 贝叶斯方法
   - 根据后验分布采样

4. LinUCB:
   - 上下文bandits
   - 考虑用户和物品特征
```

#### A/B测试

**目的**: 验证新策略是否更好

```
A/B测试流程:
1. 确定指标（北极星指标）
2. 分流（A组、B组）
3. 上线运行
4. 数据收集
5. 统计检验
6. 决策（全量上线 or 回滚）

关键:
- 流量随机分配（避免样本偏差）
- 样本量足够（统计显著性）
- 运行时间足够（避免新奇效应）
```

**统计检验**:

```
假设检验:
H0（原假设）: 新策略无效（μ_A = μ_B）
H1（备择假设）: 新策略有效（μ_B > μ_A）

p-value:
- p < 0.05: 拒绝原假设，新策略有效
- p ≥ 0.05: 不能拒绝原假设，差异不显著

置信区间:
- 95%置信区间不包含0 → 显著

实际考虑:
- 多重检验问题（多个指标）
- 长期效应（novelty effect）
- 网络效应（社交产品）
```

**案例: Netflix的A/B测试**:

```
测试: 新推荐算法
- A组（50%用户）: 旧算法
- B组（50%用户）: 新算法

指标:
- 主指标: 观看时长
- 次指标: 完播率、留存率

结果:
- 观看时长: +5% (p=0.001) ✓
- 完播率: +3% (p=0.02) ✓
- 留存率: +0.5% (p=0.06) ~ 

决策: 全量上线（主指标显著提升）
```

#### 案例2: 价格优化

**业务问题**:

```
宝洁要决定:
- 某款洗发水的建议零售价
- 考虑成本、竞品、市场需求

目标:
- 最大化利润
- 保持市场份额
- 品牌定位
```

**分析框架**:

```
1. 需求分析
   - 历史价格-销量数据
   - 价格弹性估计
   - 需求曲线拟合

2. 竞争分析
   - 竞品价格追踪
   - 市场份额变化
   - 竞争反应模型

3. 成本分析
   - 生产成本
   - 营销成本
   - 渠道成本

4. 优化模型
   - 目标函数: 最大化利润
   - 约束: 市场份额不低于X%
   - 决策变量: 价格
```

**价格弹性建模**:

```
对数线性模型:
log(Q) = β_0 + β_1 log(P) + β_2 X + ε

其中:
- Q: 销量
- P: 价格
- X: 其他因素（促销、季节）
- β_1: 价格弹性

解释:
- β_1 = -2: 价格上涨1%，销量下降2%
- |β_1| > 1: 弹性商品（降价促销有效）
- |β_1| < 1: 非弹性商品（涨价不影响太多）

实际:
- 不同产品弹性不同（必需品 vs 奢侈品）
- 不同市场弹性不同（发达 vs 发展中）
- 不同时期弹性不同（促销期 vs 平时）
```

**最优定价**:

```
简化模型:
π(p) = (p - c) × D(p)

其中:
- π: 利润
- p: 价格
- c: 成本
- D(p): 需求函数

需求函数（线性）:
D(p) = a - b·p

最优价格:
p* = (a/b + c) / 2

洞察:
- 成本越高，最优价格越高
- 需求越大（a越大），最优价格越高
- 价格敏感度越高（b越大），最优价格越低
```

#### 案例3: 促销活动优化

**业务问题**:

```
宝洁计划促销活动:
- 哪些产品打折？
- 折扣力度？
- 在哪些渠道？
- 持续多久？

目标:
- 最大化增量销售（不是总销售）
- 控制成本
- 避免品牌贬值
```

**增量分析**:

```
增量销售 = 促销期销售 - 基准销售

挑战:
1. 拉动效应（Pull-forward）
   - 促销期销量增加
   - 但促销后销量下降
   - 实际增量 < 促销期增量

2. 替代效应
   - 用户从不打折产品转向打折产品
   - 总销量不变，利润下降

3. 竞争反应
   - 竞品也打折
   - 促销效果减弱

因果推断:
- 合成控制法（Synthetic Control）
- 倍差法（Difference-in-Differences）
- 断点回归（RDD）
```

**促销响应模型**:

```
提升率 = (促销期销量 - 基准销量) / 基准销量

建模:
提升率 = f(折扣力度, 产品特征, 市场特征, 竞争环境)

方法:
- 回归分析
- 机器学习（XGBoost）
- 生存分析（促销持续时间）

优化:
- 约束: 总预算
- 目标: 最大化增量利润
- 决策: 每个产品的折扣
```

**实验设计**:

```
测试促销策略:

A/B测试:
- A组: 20%折扣
- B组: 30%折扣
- 对照组: 不打折

指标:
```

### Q1: 如何评估一个推荐系统的好坏？

**回答框架**:

```
需要从业务和算法两个维度:

业务指标（最重要）:
1. GMV/Revenue: 推荐带来的成交额
2. CTR: 点击率
3. 转化率: 点击到购买的比例
4. 用户时长: 用户停留时间
5. 留存率: 用户是否回来

算法指标:
1. 准确性: AUC、Precision、Recall
2. 排序质量: NDCG、MRR
3. 覆盖率: 推荐了多少比例的商品
4. 多样性: 推荐结果是否多样
5. 新颖性: 是否推荐用户不知道的东西

平衡:
- 短期指标 vs 长期指标
  例: 只推热门商品，CTR高但用户会腻
  
- 业务目标 vs 用户体验
  例: 推荐高价商品，利润高但用户可能反感

最终标准:
- A/B测试，看对核心业务指标的提升
```

### Q2: 如何处理推荐系统的冷启动问题？

**回答框架**:

```
冷启动分三类:

1. 新用户冷启动
   问题: 没有历史行为
   方案:
   - 热门推荐（大众喜好）
   - 引导式问卷（收集兴趣）
   - 人口统计学（年龄、性别、地域）
   - 快速学习（前几次交互快速建模）
   
2. 新物品冷启动
   问题: 没有交互数据
   方案:
   - 基于内容（类目、标签、描述）
   - 流量扶持（给新品曝光机会）
   - 相似物品（找相似的有数据的物品）
   
3. 系统冷启动
   问题: 全新系统，啥数据都没有
   方案:
   - 引入外部数据（公开数据集）
   - 迁移学习（其他平台的模型）
   - 规则引导（专家规则）

Exploration vs Exploitation:
- 不能只推已知的好（Exploitation）
- 要探索新的可能（Exploration）
- 平衡: ε-greedy、UCB、Thompson Sampling

实际经验:
- 某电商项目，新用户前10次交互用引导式推荐
- 收集兴趣后切换到个性化推荐
- 次日留存率提升15%
```

### Q3: 广告系统如何平衡用户体验和商业收入？

**回答框架**:

```
核心矛盾:
- 广告越多 → 收入越高，但用户体验差
- 广告越少 → 用户体验好，但收入低

平衡策略:

1. 广告质量
   - 相关性高的广告（用户可能感兴趣）
   - 高质量创意（不low）
   - CTR预估（确保点击率）

2. 广告密度
   - 限制广告比例（如feed中10%）
   - 根据用户容忍度动态调整
   - VIP用户减少广告

3. 广告形式
   - 原生广告（融入内容）
   - 信息流广告（不打断体验）
   - 避免强制广告（如不可跳过）

4. 长期价值
   - 优化目标: 长期留存 × 收入
   - 不只看短期收入
   - 用户流失的代价更大

5. 实验验证
   - A/B测试不同广告密度
   - 观察留存率、使用时长
   - 找到最优平衡点

数学模型:
LTV = Σ (Revenue_t - Cost_t) / (1 + r)^t
- 考虑用户生命周期价值
- 短期收入提升 vs 长期流失

实际案例:
- Facebook早期克制广告数量
- 长期建立用户信任
- 最终广告业务巨大成功
```

### Q4: 如何进行AB测试？有哪些注意事项？

**回答框架**:

```
A/B测试流程:

1. 确定目标
   - 北极星指标（如GMV、留存率）
   - 可衡量、可归因

2. 提出假设
   - 明确: "新推荐算法会提升CTR"
   - 可验证

3. 设计实验
   - 分流: 50% vs 50%（或其他比例）
   - 随机分配（避免偏差）
   - 样本量计算（统计功效）

4. 上线运行
   - 时间: 通常1-2周（覆盖完整周期）
   - 监控: 实时查看异常

5. 数据分析
   - 统计检验（t-test、卡方检验）
   - 置信区间
   - p-value < 0.05

6. 做出决策
   - 全量上线 or 回滚

关键注意事项:

1. 样本量
   - 不够大 → 检验不出差异
   - 使用功效分析预估

2. 运行时间
   - 太短 → 新奇效应（novelty effect）
   - 需要覆盖完整周期（工作日+周末）

3. 指标选择
   - 主指标: 核心业务指标
   - 次指标: 相关指标
   - 护栏指标: 不能恶化（如错误率）

4. 多重检验
   - 测多个指标 → 假阳性风险
   - 使用Bonferroni校正

5. 网络效应
   - 社交产品: A组影响B组
   - 需要集群随机化

6. 长期效应
   - 短期提升 vs 长期影响
   - 需要长期追踪

实际经验:
- 某推荐项目，A/B测试CTR提升5%
- 但发现用户多样性下降
- 最终采用折中方案
```

### Q5: 优化问题中的凸优化和非凸优化有什么区别？

**回答框架**:

```
核心区别:

凸优化:
- 目标函数是凸函数
- 局部最优 = 全局最优
- 有理论保证
- 可以高效求解

非凸优化:
- 目标函数是非凸函数
- 有多个局部最优
- 难以保证全局最优
- 深度学习的损失函数通常非凸

可视化:
凸: 碗状，一个坑
非凸: 多个坑，容易困在局部

实际影响:

凸优化（如线性回归、SVM）:
- 梯度下降一定收敛到全局最优
- 初始值不重要
- 理论性质好

非凸优化（如神经网络）:
- 梯度下降可能陷入局部最优
- 初始化很重要（Xavier、He初始化）
- 需要技巧（动量、学习率调度）

应对非凸优化:
1. 多次随机初始化，选最好的
2. 使用Adam等高级优化器
3. 正则化（让函数更平滑）
4. Batch Normalization
5. 实践中，局部最优往往也很好

商业场景:
- 凸优化: 线性规划（资源分配）
- 非凸优化: 深度学习模型训练
```
